# Folder Seal

[English version](README.md)

Плагин для Obsidian, который хранит выбранные папки волта в гите в зашифрованном виде.

Ты синкаешь волт через GitHub (или любой git-хостинг) плагином Obsidian Git, но часть заметок слишком личная, чтобы лежать там открытым текстом: документы, здоровье, дневник. Folder Seal шифрует эти папки перед тем, как они уходят в гит, и расшифровывает их на твоих устройствах. Хостинг видит только шифротекст.

Работает на ПК и на телефоне, включая iOS: это чистый JavaScript поверх WebCrypto, без `git-crypt`, без терминала, без внешних программ. Интерфейс на русском и английском, язык берётся из настроек Obsidian.

> **Статус: 0.2, ранняя версия.** Логика синхронизации покрыта тестами и проверена на ПК и iPhone, но держи бэкап заметок.

## Как это работает

Шифровать можно любые папки в любом месте волта, не пряча весь раздел:

```text
Здоровье/
  здоровье.md            открытая, в гите как обычно
  документы/  🔒         шифруется: на GitHub её нет
Машина/
  машина.md              открытая
  документы/  🔒         шифруется
_sealed/                 зашифрованные копии всех 🔒-папок — вот это и уходит в гит
```

На твоих устройствах шифруемые папки выглядят как обычные: заметки лежат на своих местах, ищутся, открываются, ссылки на них работают. В гит они не попадают: плагин сам добавляет их в `.gitignore`. Вместо них в гит уходит папка `_sealed/` с зашифрованными копиями. Там файлы с именами вроде `5e4bf3cc….seal`: ни названий, ни содержимого не видно.

Запускаешь **Folder Seal: Sync** (иконка замка или палитра команд), и плагин приводит всё в соответствие:

- изменилось у тебя → шифруется в `_sealed/`;
- пришло с git pull → расшифровывается на место;
- удаления передаются так же;
- изменилось на двух устройствах с прошлого синка → твоя версия остаётся, другая сохраняется рядом как `имя (conflict ГГГГ-ММ-ДД ЧЧММ).md`. Ничего не теряется.

Перед тем как перезаписать или удалить файл, плагин копирует его прошлую версию в `<папка>/.folder-seal-backup/<время>/`. Это внутри игнорируемой папки, так что бэкапы в гит тоже не попадают.

Сам плагин гит не трогает: синхронизирует по-прежнему Obsidian Git, а Folder Seal только шифрует и расшифровывает.

## Установка

1. Установи плагин: скачай `main.js`, `manifest.json` и `styles.css` из [последнего релиза](https://github.com/DoZhD1k/folder-seal/releases/latest) в `<волт>/.obsidian/plugins/folder-seal/` (или добавь `DoZhD1k/folder-seal` в плагине [BRAT](https://github.com/TfTHacker/obsidian42-brat)) и включи **Folder Seal** в *Настройки → Сторонние плагины*.
2. Выбери папку, которую нужно шифровать: правой кнопкой по ней (на телефоне — долгое нажатие) → **Шифровать эту папку**. Повтори для каждой такой папки. Можно и списком в настройках плагина.
3. Запусти **Folder Seal: Sync**. В первый раз плагин попросит **придумать пароль**: два поля, минимум 12 символов.
4. Закоммить и запушь.

**Пароль восстановить нельзя.** Забыл пароль — потерял зашифрованные заметки. Сохрани его в менеджере паролей.

**Если папка уже лежит в гите,** плагин откажется её шифровать: `.gitignore` не мешает гиту отслеживать файлы, которые он уже знает, и они продолжили бы уходить на GitHub открытым текстом. Сначала убери её из гита: на компьютере выполни `git rm -r --cached "Здоровье/документы"` и закоммить. Старые версии этих файлов останутся в истории гита. Проще всего шифровать новую папку и переносить в неё файлы.

### Другие устройства

Если ты коммитишь `.obsidian/plugins` (Obsidian Git по умолчанию коммитит), плагин и его настройки приедут со следующим pull. На iPhone после pull перезапусти Obsidian, чтобы он подхватил новый плагин.

**Сначала pull, потом Sync.** Плагин попросит **ввести пароль**: одно поле, тот же пароль. Дальше устройство его помнит.

Если на устройстве, где пароль уже должен быть, Sync просит *придумать* пароль (два поля), значит, зашифрованная папка ещё не приехала. Закрой окно и сделай pull: второй пароль развёл бы устройства на разные ключи.

## Как пользоваться каждый день

```text
pull  →  Sync  →  работаешь  →  Sync  →  commit и push
```

Sync после pull, чтобы получить то, что прислали другие устройства, и перед push, чтобы отправить своё. Запускать Sync чаще не вредно: неизменённые файлы дают побайтно тот же шифротекст, и гит не видит изменений.

Кнопка «commit and sync» в Obsidian Git сначала коммитит, потом делает pull. Так тоже можно: Sync, кнопка, и ещё раз Sync, чтобы расшифровать пришедшее. Зашифрованные файлы никогда не правятся на месте: каждая версия — новый файл, а старый удаляется. Поэтому гит сливает работу двух устройств без конфликтов, даже если обе правили одну заметку.

## Ссылки на зашифрованные заметки

Работают как обычно: `[Анализы](документы/анализы.md)` из открытой заметки открывается на любом устройстве, где был Sync. На устройстве, где Sync ещё не делали, ссылка будет битой.

Учти: **текст ссылки лежит в открытой заметке**, поэтому на GitHub видно, что файл `анализы.md` существует. Содержимое не видно. Если само название палевное, ставь ссылку из такой же зашифрованной заметки.

## Пароль

| Что нужно | Что делать |
| --- | --- |
| Задать пароль | Первый Sync в волте, где ещё ничего не зашифровано. |
| Сменить пароль | **Folder Seal: Сменить пароль** — старый, потом новый дважды. Файлы не перешифровываются, другие устройства ничего вводить не будут. |
| Пароль мог кто-то узнать | **Folder Seal: Сменить пароль и перешифровать всё**. Все файлы шифруются заново новым ключом: старый пароль не откроет ничего, даже старые версии из истории гита. Перед этим синхронизируй и запушь остальные устройства. После — каждое из них один раз спросит новый пароль. |
| Не хранить пароль на устройстве | Выключи в настройках «Запомнить пароль»: тогда он спрашивается каждый сеанс. Или команда **Забыть пароль на этом устройстве**. |

Если на другом устройстве была незапушенная правка во время перешифровки, ничего не потеряется: плагин прочитает её старым ключом и перешифрует. Рядом может появиться копия-конфликт со старым текстом файла — её можно удалить.

## Если что-то пошло не так

- **Пропали данные приложения** (переустановил Obsidian, новый телефон, очистилось хранилище): склонируй волт, Sync, введи пароль — всё расшифруется из гита. Если на этом устройстве оставались расшифрованные файлы, одинаковые совпадут, разные станут копиями-конфликтами. Ничего не удалится.
- **«wrong passphrase»** — неверный пароль. Ничего не тронуто.
- **«cannot decrypt …»** — файл повреждён или зашифрован ключом, которого это устройство не знает (после перешифровки на устройстве, которое ещё не синкалось). Сделай Sync на том устройстве, запушь, потом pull здесь. Пока это не исправлено, Sync ничего не меняет.
- **Переименовал шифруемую папку** — плагин сам обновит список и `.gitignore`.
- **Убрал папку из списка** («Перестать шифровать эту папку») — она перестаёт синхронизироваться, но остаётся в `.gitignore`, так что в гит открытым текстом не уйдёт. Её зашифрованные копии остаются в `_sealed/`.

## Настройки

| Настройка | По умолчанию | Что делает |
| --- | --- | --- |
| Шифруемые папки | — | По одной на строку, путь от корня волта. Каждая автоматически попадает в `.gitignore`. |
| Папка зашифрованного | `_sealed` | Зашифрованные копии всех папок. Её коммить. |
| Скрыть папку зашифрованного | вкл | Не показывать её в списке файлов. |
| Запомнить пароль на этом устройстве | вкл | Хранит ключ в памяти приложения на этом устройстве (не в волте и не в гите). |

Настройки лежат в `.obsidian/plugins/folder-seal/data.json` и синхронизируются вместе с волтом. Поэтому **названия шифруемых папок видны на GitHub**, их содержимое — нет.

## Безопасность

**Защищает от:** того, кто получил твой git-репозиторий: угнанный аккаунт GitHub, токен или сам хостинг. Он увидит названия шифруемых папок (из настроек и `.gitignore`), количество файлов, примерные размеры и время изменений. Не названия файлов и не содержимое.

**Не защищает от:** того, у кого есть доступ к твоему разблокированному устройству. Там расшифрованные заметки — обычные файлы. Используй шифрование диска (BitLocker, FileVault) и код-пароль на телефоне.

Подробности:

- **Мастер-ключ:** 96 случайных байт, делятся на три 256-битных ключа: для содержимого, для имён файлов и для IV.
- **Пароль** запирает мастер-ключ: PBKDF2-SHA-256, 600 000 итераций, случайная соль 16 байт → ключ AES-256-GCM. Запертый мастер-ключ лежит в `_sealed/folder-seal.json` вместе с солью. Смена пароля перезапирает только его.
- **Содержимое:** AES-256-GCM. Каждый файл аутентифицирован, поэтому подмена или неверный ключ обнаруживаются, и синк останавливается, ничего не записав.
- **Имена файлов:** зашифрованный файл называется HMAC-SHA-256 от своего пути. Имя скрыто, но одинаково на всех устройствах. Настоящий путь лежит внутри шифротекста.
- **Детерминированное шифрование:** IV — это HMAC от содержимого, поэтому одинаковый вход даёт одинаковый выход. Так история гита остаётся чистой, но одинаковые файлы видно как одинаковые. `git-crypt` идёт на тот же компромисс.

### Форматы

```text
_sealed/folder-seal.json
  { version: 2, keyId, kdf, iterations, salt, lockedKey }
  lockedKey = IV (12) | AES-256-GCM(мастер-ключ), ключ = PBKDF2(пароль, salt)
  keyId     = hex(SHA-256(мастер-ключ))[0..16]

_sealed/<id>.<версия>.seal
  "FSL1" (4 байта) | IV (12 байт) | шифротекст AES-256-GCM + тег
  содержимое = длина заголовка u32 BE | JSON {"v":1,"path":"путь/от/корня/волта"} | байты файла
  IV         = HMAC-SHA-256(ключ IV, содержимое)[0..12]
  id         = hex(HMAC-SHA-256(ключ имён, путь))[0..32]
  версия     = hex(SHA-256(зашифрованные байты))[0..16]
```

## Обновление с 0.1

0.2 не читает зашифрованную папку 0.1: поменялся формат ключа. Перед обновлением на всех устройствах сделай Sync с 0.1, чтобы расшифрованные файлы были на месте. Потом удали старую зашифрованную папку, обнови плагин, добавь папку в список и запусти Sync — он создаст новый пароль и зашифрует всё заново. На остальных устройствах: pull, удалить старые расшифрованные файлы, Sync.

## Ограничения

- Sync запускается вручную. Автозапуск вокруг pull/push Obsidian Git — в планах.
- Переименование файла — это удаление плюс новый файл.
- Каждый синк читает и хэширует все шифруемые папки. Для заметок нормально, для гигабайтов медиа медленно.

## Разработка

```bash
npm install
npm test          # юнит-тесты: шифрование, ключи, синк нескольких устройств через git
npm run dev       # пересобирать main.js при изменениях
npm run build     # проверка типов + продакшн-сборка
```

Чтобы попробовать вживую, скопируй `main.js`, `manifest.json` и `styles.css` в `.obsidian/plugins/folder-seal/` тестового волта и перезапусти Obsidian.

```text
src/crypto.ts     шифрование файлов и id — чистый WebCrypto
src/keyring.ts    мастер-ключ, пароль, folder-seal.json
src/sync.ts       трёхстороннее сравнение и перешифровка поверх абстрактного SealIO
src/vault-io.ts   SealIO поверх волта Obsidian, бэкапы
src/git-index.ts  чтение .git/index: не даёт шифровать папку, которую гит уже отслеживает
src/i18n.ts       строки интерфейса, en и ru
src/main.ts       плагин: команды, меню папок, окна пароля, настройки, защита .gitignore
tests/            vitest; устройства и git-слияние изображаются в памяти
```

`sync.ts` и `keyring.ts` ничего не знают про Obsidian, поэтому все правила тестируются в Node. Если меняешь их, добавь сценарий в `tests/`.
